# 系统 AI 外发合规评估与敏感文件治理方案

> 评估日期：2026-10-28
> 评估对象：研发知识智能管理平台（FastAPI + Streamlit + SQLite）及其 QQ 机器人
> 性质说明：本文是技术合规评估与改造建议，不构成法律意见；数据定级、合同与员工告知等最终以公司法务、保密、网信部门意见为准。

---

## 一、结论摘要

### 1.1 一句话结论

当前系统是 **“默认全量外发、无分级、无脱敏、无审计、无授权”** 的 AI 使用模式：文件一上传就自动把正文截断后发给 DeepSeek，问答会把检索到的原文片段发给 DeepSeek，QQ 机器人还能把文件原样发到 QQ。对合同、财务、人员、网络台账、等保报告等敏感数据，这个模式 **风险高，建议按“不合规”处理并立即整改**。

### 1.2 红黄绿判断

| 区域 | 判断 | 说明 |
|---|---|---|
| 网络通讯台账（站点/设备/IP-MAC/拓扑/等保资料） | 🟢 相对安全 | 代码中 **没有调用任何 AI**，解析全部是本地规则；应固化为“AI 禁入区” |
| 文件管理（上传自动分类/摘要） | 🔴 高风险 | 每个支持的文件上传后自动发 6000~8000 字到 DeepSeek，无提示、无拦截 |
| 合同管理 | 🔴 高风险 | 合同正文 8000+2000 字发 DeepSeek，含甲乙方、金额、付款节点 |
| 经费/财务资料 | 🔴 高风险 | 发票/结算单正文发 DeepSeek，含金额、税号、银行信息 |
| 成果台账 | 🟠 中高风险 | 专利/论文/软著证书正文发 DeepSeek，可能含未公开技术 |
| 智能问答/跨项目分析 | 🔴 高风险 | 最多 40 段×1200 字（约 4.8 万字）原文片段发 DeepSeek，可跨项目 |
| QQ 机器人 | 🔴 高风险 | 可把后端文件原样上传到 QQ（腾讯），无敏感度过滤；入站文件落在 `qq_tmp` |
| 备份/密钥/数据库 | 🟠 中高风险 | 备份已 Fernet 加密，但 `.env`、`rd_platform.db`、`chat_history.json` 明文；密钥与备份同机 |

### 1.3 三个最严重的问题

1. **等保测评报告、拓扑图、漏洞/整改清单属于明确要求保密的资料**，若通过“文件管理”上传，会被自动发给第三方大模型。  
   《电力监控系统安全防护规定》（发改委 27 号令）第 27 条明确：安全防护方案、安全测试评估报告和漏洞隐患细节等资料应按国家要求做好保密工作，禁止关键技术和产品扩散。
2. **合同、财务、未公开专利属于商业秘密**，而 DeepSeek 开放平台协议第 4.1 条要求开发者保证输入“不涉及任何国家秘密、商业秘密或其他可能会对国家安全或者公共利益造成不利影响的数据”。当前默认外发，存在违约与泄密双重风险。
3. **姓名 + IP + MAC + 部门 + 地点属于个人信息**，当前未告知、未取得同意、未做个人信息保护影响评估，直接委托第三方 API 处理，不符合《个人信息保护法》第 13/17/23/55 条的要求。

## 二、事实：当前 AI 外发点清单

### 2.1 数据流

```
文件上传
  → 本地提取文本（PDF/Word/Excel/OCR）
  → 截断 6000~10000 字
  → HTTPS POST https://api.deepseek.com/chat/completions
  → 结果写回数据库（分类/摘要/合同字段/成果字段/财务字段）

智能问答
  → 本地检索 project_files / achievements 文本块
  → 取最多 40 块 × 1200 字（约 4.8 万字）
  → DeepSeek
  → 回答返回页面；QQ 场景再转发到腾讯 QQ

QQ 机器人
  → 文本：调用后端 /ask，把回答发到 QQ
  → 文件：/search 检索 → /files/{id}/download → 上传到 QQ
  → 入站附件：下载到 qq_tmp（未入库、未加密）
```

### 2.2 12 个调用点

| # | 功能 | 代码位置（约） | 发送内容 | 字符上限 | 触发方式 |
|---|---|---|---|---|---|
| 1 | 文件自动分类/摘要 | `main.py` `_classify_file` | 文件名 + 正文头 6000 + 尾 2000 | 8000 | **上传即触发** |
| 2 | 合同字段抽取（旧） | `main.py` `_extract_contract_fields` | 合同正文头 6000 + 尾 2000 | 8000 | 合同上传后台 |
| 3 | 合同字段抽取（新） | `main.py` `_extract_contract_fields` | 合同正文头 8000 + 尾 2000 | 10000 | 合同上传/文件导入 |
| 4 | 财务单据抽取 | `main.py` `_extract_financial_doc_fields` | 单据正文头 6000 + 尾 2000 | 8000 | 财务资料上传后台 |
| 5 | 成果字段抽取 | `main.py` `_extract_achievement_fields` | 证书正文头 6000 + 尾 1500 | 7500 | 成果上传后台 |
| 6 | 文件摘要 | `main.py` `_call_deepseek_summary` | 正文前 4000 | 4000 | 手动点“生成摘要” |
| 7 | 资料分类摘要（旧） | `main.py` `_extract_document_summary` | 正文前 6000 | 6000 | 补提取/后台 |
| 8 | 智能问答 | `main.py` `ask_question` + `utils/ai.py` `_call_deepseek` | 检索片段 + 问题 | 约 48000 | 用户提问 |

| 10 | 项目合同统计 | `main.py` `project_stats` | 全部合同字段 JSON（甲乙方/金额/日期） | 随合同数增长 | 用户提问 |
| 11 | 项目资料总结 | `main.py` `documents_summarize` | 全部资料摘要 | 随资料数增长 | 用户提问 |
| 12 | 跨项目分析 | `main.py` `_extract_cross_project_target` / `_call_deepseek_cross_project` | 问题 + 文件清单/统计/摘要 | 随文件数增长 | 用户提问 |

> 以上调用全部是 `requests.post` 直连 `DEEPSEEK_API_URL`，没有统一网关、没有策略判断、没有调用审计。

### 2.3 QQ 机器人的两条外发路径

- `qq_bot.py` `_do_file_search`：后端 `/search` 命中文件后，`GET /files/{id}/download` 取原文件，再上传到 QQ；**没有任何密级/关键词过滤**。
- `qq_bot.py` 文本问答：后端 `/ask` 的回答（可能包含合同/资料原文）发到 QQ。
- 入站附件：保存到 `qq_tmp`，未加密、未纳入备份；`QQ_ALLOWED_OPENIDS` 为空时首次使用者会被自动写入白名单并成为“唯一授权用户”。

### 2.4 存储与密钥现状

- `.env`：DeepSeek API Key、QQ App Secret、BOT_TOKEN、BACKUP_KEY、ADMIN_PASSWORD_HASH 均为明文；`.gitignore` 已排除，但无法阻止云盘/目录同步。
- `rd_platform.db`：SQLite 明文，含项目、合同字段、文件路径、AI 摘要、网络台账（设备/IP-MAC/等保资料元数据/整改项）。
- `chat_history.json`：问答历史明文。
- `audit_archive/*.jsonl`：审计归档明文（仅元数据，不含正文）。
- `backups/backup_*.zip.enc`：数据库 + 上传目录，Fernet 加密；密钥在同一台机器的 `.env` 中。
- 备份范围：`DB_PATH` + `UPLOAD_DIR`；不包含 `.env`、`chat_history.json`、`qq_tmp`、`audit_archive`。
- 当前项目根目录位于 `C:\Users\石霈宇\WorkBuddy\...`：**若 WorkBuddy 目录被云盘同步，`.env`、数据库、聊天记录、备份会整体上云**，这比 AI 外发本身更严重，需优先确认。

## 三、数据分类分级建议

> 以下为工作建议，最终以集团/公司数据分类分级目录和保密制度为准。

| 级别 | 定义 | 系统内典型数据 | AI 策略 |
|---|---|---|---|
| **L4 核心/特别重要** | 一旦泄露可能危害电力系统安全、关键信息基础设施或国家安全 | 电力监控系统拓扑图、接入点图、安全防护方案、等保测评报告全文、漏洞扫描/渗透测试结果、整改问题清单、纵向加密/横向隔离配置、生产控制大区 IP/MAC/端口 | **禁止任何外部 API、禁止 QQ、禁止公网**；仅本地加密存储，专人审批 |
| **L3 重要/敏感** | 泄露可能造成较大经济损失、商业秘密泄露或个人信息侵权 | 全公司 IP/MAC 台账（含姓名/部门/地点）、设备台账（型号/固件/维保）、合同全文/金额/甲乙方、发票/结算单、未公开专利/论文/软著、项目申报书/可研/验收材料、人员名单/电话/邮箱 | **默认禁止外发**；必须“脱敏 + 审批”或本地模型；加密存储、最小权限 |
| **L2 内部** | 仅限公司内部使用，泄露影响有限 | 已结项项目资料、内部通知、脱敏后的统计报表、公开前的普通文档 | 云 API 可用，但需去标识、最小化、留审计 |
| **L1 公开** | 已公开或可公开 | 公开标准、公开新闻、已公开专利、公开招标公告 | 可用云 API |

**关键判断**：
- 等保测评报告中的“问题清单/整改建议/拓扑/IP”是 L4；不要因为它是 Word/PDF 就当成普通资料。
- IP/MAC 与姓名、部门、地点组合后是个人信息；单独 MAC 也可能构成设备标识符。
- 合同金额、甲乙方、付款节点是商业秘密；财务票据还含税号、银行账号。
- 未公开的专利/论文是商业秘密，不能按“成果”默认外发。

## 五、当前主要缺口（按代码）

1. **没有 AI 总开关/分级开关**：`DEEPSEEK_API_KEY` 一配，所有功能默认可外发。
2. **上传即外发**：`_classify_file` 在文件上传流程中自动调用，无用户确认。
3. **没有敏感识别**：不区分“公开标准”和“等保测评报告”。
4. **没有脱敏**：IP、MAC、姓名、电话、金额、合同号原样发送。
5. **没有 AI 调用审计**：无法回答“谁在何时把哪个文件发给了哪个模型、发了多少字”。
6. **没有供应商数据协议**：未确认“不用于训练、留存期限、删除机制、子处理者”。
7. **QQ 是第二外发通道**：文件原样上传到腾讯，且入站文件落在未加密临时目录。
8. **密钥与数据同机明文**：`.env`、SQLite、`chat_history.json` 未加密；备份密钥与备份同机。
9. **没有留存/删除策略**：DeepSeek 侧、QQ 侧、本地临时文件均无明确期限。
10. **没有出站网关/白名单**：`DEEPSEEK_API_URL` 可被改到任意地址；`requests` 默认读取系统代理，存在被代理截获风险。
11. **网络台账虽未接 AI，但没有硬隔离**：用户仍可把同一份等保报告上传到“文件管理”，从而被外发。
12. **AI 结果自动入库**：分类/摘要/合同字段直接写库；分类结果没有人工确认，错误会长期存在。

## 六、治理方案

### 6.1 立即（P0，本周内，先“禁、拦、审、约”）

| # | 动作 | 验收标准 |
|---|---|---|
| 1 | 增加 `AI_MODE` 总开关，默认 `off`；按模块/密级放行 | 关闭后所有 AI 按钮不可用，后端不发出任何 `api.deepseek.com` 请求 |
| 2 | 增加敏感文件识别（文件名/路径/关键词/正则） | 上传“等保测评报告/拓扑/漏洞/IP-MAC/合同/发票”时自动判定为敏感，跳过 AI |
| 3 | 网络台账设为 AI 禁入区 | `net_reports`、`net_topologies` 及 `UPLOAD_DIR/net/**` 永不进入 AI；页面显示“本模块不调用 AI” |
| 4 | 上传前提示 + 二次确认 | 敏感文件默认“仅本地解析”，用户必须勾选“我确认已脱敏/已获授权”才可调用云 API；记录确认人/时间 |
| 5 | 增加 `ai_audit` 调用审计 | 每次调用记录：人、模块、文件 ID、密级、字符数、模型、端点、放行/拦截、原因；不记录正文 |
| 6 | 关闭 QQ 文件外发 | `QQ_FILE_EGRESS=off`；确需开启时只允许 L1/L2，并逐次审计 |
| 7 | 收紧密钥与目录 | `.env` 仅当前用户可读；轮换 DeepSeek Key；确认 WorkBuddy 是否云同步；关闭 Streamlit 使用统计 |
| 8 | 向 DeepSeek 索取企业协议/数据处理说明 | 书面确认：不用于训练、留存期限、删除机制、子处理者、境内存储；拿不到则云 API 只允许 L1 |

### 6.2 短期（P1，2~4 周，分级 + 脱敏 + 路由）

1. **文件打标**：新增 `sensitivity`（L1~L4）、`data_category`、`ai_policy`、`owner` 字段；上传时自动判定，允许人工修正。
2. **统一 AI 网关**：所有调用改走 `utils/ai_gateway.py`，由策略引擎决定“禁止/本地/脱敏上云/原样上云”。
3. **脱敏管道**：IP、MAC、姓名、电话、邮箱、身份证、银行卡、合同号、备案号、金额、系统名/站点名替换为占位符；映射表只存本地。
4. **本地规则替代**：分类、合同要素、财务金额、成果字段优先走正则/表头/模板规则；AI 只做兜底。
5. **审批流**：L3 文件调用云 API 需管理员审批；L4 一律禁止。
6. **PIPIA**：对“姓名+IP+MAC+电话”的处理做个人信息保护影响评估并留档；更新员工告知。
7. **供应商协议**：签署数据处理协议/保密协议，明确不训练、不留存或短留存、可删除、可审计。
8. **留存与删除**：本地 AI 审计日志保留 6~12 个月；临时文件 7 天清理；DeepSeek 侧按协议删除。

### 6.3 中期（P2，1~3 个月，本地化 + 网关）

1. **本地大模型**：在本地服务器/GPU 部署 7B~14B 模型（Qwen/DeepSeek 蒸馏版），承接 L3 的分类、抽取、摘要、问答；L4 只做本地规则/检索，不经过生成式模型。
2. **AI 网关**：统一出站、模型路由、DLP、审计、配额、熔断；只允许白名单域名。
3. **分类分级平台对接**：把集团数据分类分级目录落到文件标签，自动继承。
4. **监控与演练**：出站流量监控、异常调用告警、泄露应急演练、红队测试（提示注入/越权检索）。
5. **制度**：AI 使用管理办法、敏感数据清单、供应商清单、年度合规评估。

### 6.4 长期

- 通过等保/关基年度评估，把“第三方 AI 处理”纳入供应链与数据安全评估。
- 对涉密/核心数据做到“不出机房、不出安全域”。
- 定期复核模型/供应商/数据目录变化。

## 七、技术落地设计（可直接改造）

### 7.1 配置项

```ini
# .env
AI_MODE=off                 # off | local | redacted_cloud | full_cloud
AI_ALLOW_CLOUD_LEVELS=L1,L2 # 允许上云的密级
AI_MAX_CHARS=6000           # 单次外发上限
AI_REDACT=true              # 上云前脱敏
AI_AUDIT=true               # 记录调用审计
AI_ENDPOINT_ALLOWLIST=api.deepseek.com
QQ_FILE_EGRESS=off          # QQ 文件外发总开关
```

### 7.2 统一网关（伪代码）

```python
# utils/ai_gateway.py
def guarded_chat(module: str, text: str, meta: dict) -> str | None:
    level = meta.get("sensitivity") or classify_sensitivity(meta, text)
    if not policy.allow(level, meta):          # L4 永远 False；L3 需审批
        audit(module, meta, level, len(text), "blocked", "policy")
        return None
    if policy.needs_redact(level):
        text, mapping = redact(text)           # IP/MAC/姓名/金额/合同号...
        audit(module, meta, level, len(text), "redacted", f"{len(mapping)} entities")
    else:
        audit(module, meta, level, len(text), "sent", "")
    return call_deepseek(text)                 # 只在这里 requests.post
```

**改造原则**：
- 删除/替换 `main.py`、`utils/ai.py` 中 12 处直接 `requests.post`；
- 所有调用必须带 `module`、`ref_type`、`ref_id`、`sensitivity`；
- 网关内统一超时、重试、限流、错误处理；
- 禁止业务代码直接读 `DEEPSEEK_API_KEY`。

### 7.3 敏感识别规则（建议）

**路径/文件名关键词**：
`等保`、`测评报告`、`等级保护`、`拓扑`、`接入点`、`漏洞`、`渗透`、`扫描`、`安全防护方案`、`纵向加密`、`横向隔离`、`堡垒机`、`IP`、`MAC`、`备案`、`密码`、`口令`、`账号`、`身份证`、`手机号`、`工资`、`合同`、`发票`、`结算`、`暂估`、`专利`、`论文`、`软著`、`未公开`、`内部`、`机密`、`秘密`。

**路径规则**：
`UPLOAD_DIR/net/reports/**`、`UPLOAD_DIR/net/topology/**`、`等保测评/**`、`网信设备台账/**`、`IP与MAC/**`。

**正则**：
- IPv4/IPv6、MAC（`([0-9A-Fa-f]{2}[:-]){5}[0-9A-Fa-f]{2}`）
- 身份证、手机号、邮箱、银行卡
- 备案号（如 `\d{8,}-\d{4,}`）、合同编号、金额
- 坐标/经纬度（如涉及大坝/电站位置）

**文档结构**：
- 表格表头含“IP地址/MAC地址/设备名称/所属系统”
- 报告章节含“测评结论/问题清单/整改建议/漏洞”
- 拓扑图（.vsd/.vsdx/.jpg 且文件名含“拓扑/接入点”）

| 邮箱 | `a@b.com` | `[EMAIL_001]` |
| 合同号 | `HD-2026-001` | `[CONTRACT_001]` |
| 备案号 | `51342226672-22004` | `[FILING_001]` |

- 映射表存本地加密表，**绝不随 prompt 发送**；
- 摘要/分类场景可只回填占位符，不必还原；
- 需要还原时（如合同字段抽取），在本地对输出做映射回填，并记录。

### 7.5 AI 审计表

```sql
CREATE TABLE ai_audit (
  id INTEGER PRIMARY KEY,
  ts DATETIME,
  username VARCHAR(50),
  module VARCHAR(30),          -- classify/contract/finance/achievement/ask/...
  ref_type VARCHAR(20),        -- file/contract/report/query
  ref_id INTEGER,
  sensitivity VARCHAR(5),      -- L1~L4
  chars INTEGER,
  action VARCHAR(20),          -- sent/blocked/redacted/local
  reason VARCHAR(200),
  endpoint VARCHAR(100),
  model VARCHAR(50),
  request_id VARCHAR(100)
);
```

- 不记录 prompt/response 正文；
- 可按月统计“外发文件数/字符数/拦截数”，作为合规报表；
- 审计日志保留 6~12 个月，防篡改（可选哈希链）。

### 7.6 网络台账加固

- `net_reports`、`net_topologies` 增加 `sensitivity='L4'`、`ai_policy='block'`；
- 网络台账的文本提取只用于本地展示/检索，**不写入 `project_files.content`**，不进入全局 `/search` 和 `/ask`；
- 文件存放在独立目录 `UPLOAD_DIR/net/`，ACL 仅管理员；
- UI 明确提示“本模块不上传任何内容到 AI”；
- 若用户把同文件上传到“文件管理”，由文件名/路径规则识别并阻止。

### 7.7 QQ 机器人加固

- `QQ_FILE_EGRESS=off` 默认；开启需二次确认；
- 文件发送前按密级过滤，L3/L4 拒绝；
- 入站附件：扫描、加密、限期清理，不自动进入知识库；
- 白名单为空时不要“首个用户自动授权”，改为管理员显式添加；
- QQ 文本回答也要过 DLP（避免把合同/台账原文发到 QQ）。

### 7.8 供应商与合同

向 DeepSeek 索取/确认：
1. 企业版服务协议、数据处理协议（DPA）；
2. 输入/输出是否用于模型训练，如何关闭；
3. 数据留存期限、删除机制、是否可导出/删除；
4. 子处理者清单、数据中心位置（境内）；
5. 安全认证（等保/ISO 27001/ISO 27701）、事件通知、审计权；
6. 若无法满足：仅允许 L1 公开数据走云 API。

### 11.2 默认策略

```
ai_enabled=1
ai_mode=balanced
ai_l3_auto=1      # L3 后台任务默认脱敏后自动外发；可在侧边栏关闭
ai_redact=1
ai_max_chars=50000
```

> 说明：`ai_l3_auto=1` 是策略 B 的“平衡点”：合同/财务/成果等后台自动抽取仍可用，但会先脱敏并留审计；如果要求“每份 L3 都人工确认”，把侧边栏「L3 自动脱敏后外发」关闭即可，届时 L3 后台任务会被拦截，需人工处理。

### 11.3 实测

- L4 提问“等保测评报告结论” → HTTP 403，明确提示禁止外发。
- L3 提问“合同金额/甲方乙方”未勾选确认 → HTTP 403；勾选后可脱敏外发。
- 合同文本中的电话/IP/MAC → 发送前替换为 `[PHONE]`/`[IP]`/`[MAC]`。
- `ai_l3_auto=0` 时，后台合同抽取被拦截。
- `ai_audit` 已记录 sent/redacted/blocked 三类动作。
